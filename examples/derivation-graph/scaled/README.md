# Scaled Fauxbooks Demo (Phase 09)

## Overview

This demo scales the fauxbooks derivation graph to enterprise size: four synthetic
CSV datasets totalling 1 880 committed rows, producing a 1 980-leaf token graph
rooted at `operating_income`. The e2e tests assert byte-identical golden bundles,
a byte-identical golden trace, the contribution invariant
(`sum(leaf contributions) == operating_income.ValueCanonical`), and full
`bundle.Verify` / `bundle.Replay` determinism across independent runs. A companion
broken-sibling dataset (`broken/`) introduces two deliberate semantic breakages —
a dropped payroll row and a tampered expense amount — to prove that
`bundle.Verify` remains unaffected by semantic errors while row-level CSV
reconciliation surfaces exactly the expected anomalies, and that a cross-run
comparison on `operating_income.ValueCanonical` reveals the value shift.

## Datasets

### Happy path (`data/`)

| File | Rows | Columns |
|---|---|---|
| `data/payroll.csv` | 100 | `employee_id`, `department`, `salary`, `bonus` |
| `data/expenses.csv` | 500 | `expense_id`, `category`, `department`, `amount`, `date` |
| `data/revenue.csv` | 1 200 | `txn_id`, `product`, `region`, `amount` |
| `data/refunds.csv` | 80 | `refund_id`, `product`, `region`, `amount` |

Generated by `gen/gen.go` with seed 42 and per-table sub-seeds (payroll +1,
expenses +2, revenue +3, refunds +4). Amounts are canonical decimal strings.
The CSV bytes are committed; the generator is not invoked at test time.

### Broken sibling (`broken/data/`)

Two deliberate mutations relative to the happy-path CSVs:

- **EMP-0042 dropped** — `broken/data/payroll.csv` has 99 rows; `EMP-0042` is
  absent. Surfaces as `OutcomeMissingRight` when happy-path CSV (left) is
  reconciled against the broken CSV (right).
- **EXP-00001 amount +$0.01** — one row in `broken/data/expenses.csv` has its
  `amount` field incremented by `0.01`. Surfaces as `OutcomeMismatch` with
  non-empty `Differences` on string comparison of the canonical decimal.
- `revenue.csv` and `refunds.csv` are identical to the happy-path copies.

The broken bundle is internally self-consistent: its leaf contributions sum to
its own `operating_income` value, so `trace.Trace` does NOT return
`ErrContributionMismatch`. The breakages are detectable only via CSV
reconciliation and a cross-run value comparison.

## Derivation Graph

```
operating_income     = calc.subtract(net_revenue, total_opex)
net_revenue          = calc.subtract(gross_revenue, total_refunds)
gross_revenue        = calc.add(gross_revenue_batch1, gross_revenue_batch2)
gross_revenue_batch1 = calc.sum(revenue tokens 1..1000)      # 1000 leaves
gross_revenue_batch2 = calc.sum(revenue tokens 1001..1200)   #  200 leaves
total_refunds        = calc.sum(80 refund tokens)            #   80 leaves
total_opex           = calc.add(total_payroll, total_expenses)
total_payroll        = calc.add(total_salaries, total_bonuses)
total_salaries       = calc.sum(100 salary tokens)           #  100 leaves
total_bonuses        = calc.sum(100 bonus tokens)            #  100 leaves
total_expenses       = calc.sum(500 expense tokens)          #  500 leaves
```

**Leaf count: 1 980** (100 salary + 100 bonus + 500 expenses + 1 200 revenue +
80 refunds). Revenue exceeds the CLI `maxCalcInputs` limit of 1 000, so it is
split into two batches before being combined with `calc.add`. This adds two
intermediate nodes but does not change the leaf count. The contribution invariant
holds through the batch nodes transparently.

Payroll contributes 200 leaves (not 100) because `salary` and `bonus` require
separate `read-mint` calls — each call has exactly one `output_path`, so each
column projection yields its own token.

## Run the Demos

All commands are run from the repository root.

### Happy-path end-to-end test

```bash
go test -v -run TestScaledFauxbooksEndToEnd ./examples/derivation-graph/scaled/
```

Runs the full CLI sequence, asserts byte-equal golden bundle and trace, checks
`bundle.Verify`, `bundle.Replay`, and the contribution invariant.

Additional happy-path tests:

```bash
go test -v -run TestScaledFauxbooksOperatingIncomeValue ./examples/derivation-graph/scaled/
go test -v -run TestScaledFauxbooksLeafCount           ./examples/derivation-graph/scaled/
go test -v -run TestScaledFauxbooksReplayDeterminism   ./examples/derivation-graph/scaled/
```

### Happy-path HTML report test

```bash
go test -v -run TestScaledFauxbooksHTMLReport ./examples/derivation-graph/scaled/
```

Builds an audit pack from the bundle, renders HTML via `audit-html`, and asserts
byte-equal against `golden.report.html`.

### Broken-sibling end-to-end test

```bash
go test -v -run TestBrokenFauxbooksEndToEnd ./examples/derivation-graph/scaled/broken/
```

Runs the broken CLI sequence, reconciles both CSVs, asserts `OutcomeMissingRight`
for EMP-0042 and `OutcomeMismatch` for the tampered expense row, and confirms the
cross-run `operating_income` value inequality.

### Broken-sibling HTML report test

```bash
go test -v -run TestBrokenFauxbooksHTMLReport ./examples/derivation-graph/scaled/broken/
```

Renders the broken audit pack as HTML and asserts byte-equal against
`broken/golden.report.html`. The rendered report keeps the contribution
invariant `OK`; reconciliation mismatches remain visible as distinct business
data anomalies.

### Full suite

```bash
go test ./examples/derivation-graph/scaled/...
```

## Generate an HTML Report Directly

First build the `provenant` binary:

```bash
go build -o /tmp/provenant ./access/cmd/provenant/
```

Then produce an audit pack from an existing bundle and render it:

```bash
# Happy path
/tmp/provenant pack --bundle examples/derivation-graph/scaled/golden.bundle.json \
                    --out /tmp/scaled-happy.pack.json
/tmp/provenant audit-html --pack /tmp/scaled-happy.pack.json \
                           --out /tmp/scaled-happy.html

# Broken sibling
/tmp/provenant pack --bundle examples/derivation-graph/scaled/broken/golden.bundle.json \
                    --out /tmp/scaled-broken.pack.json
/tmp/provenant audit-html --pack /tmp/scaled-broken.pack.json \
                           --out /tmp/scaled-broken.html
```

Open either HTML file directly from disk — no server or network access needed.

## What's in the Report

The `audit-html` renderer produces a single self-contained HTML file with eight
sections (no external assets or network dependencies):

| Section | What it shows | Why it matters |
|---|---|---|
| **Header** | `schema_version`, `bundle_sha256` (full hex), `run_id`, `tenant_id` | Ties the report to an exact immutable bundle |
| **Summary tiles** | Token count, captured-reads count, audit-entry count, mismatch count, submitted-answer value | At-a-glance health of the audit run |
| **Submitted answer** | `token_id`, `value_canonical`, `unit`; provenance note | Confirms the reported value and its grounding |
| **Reconciliation outcomes** | Outcome counts table + mismatches table (`result_id`, `outcome`, `key`, `field`, `left`, `right`, `reason`) | Surfaces every anomaly between two datasets; absent when no reconciliation data is present |
| **Derivation graph** | Nested tree from submitted-answer root to every leaf, with contribution amounts; `Contribution invariant: OK` or `VIOLATED` banner | Proves every number traces back to a source row; shows any invariant violation in red |
| **Captured reads** | Source name, selector, sha256 (first 16 hex chars), bytes read | Verifies which file versions were read and their hashes |
| **Audit chain** | Per-kind entry histogram; prev-hash continuity check (`OK` or `BROKEN` with first broken link) | Detects any tampering with the audit log sequence |
| **Manifest** | Artifact name and full sha256 | Enumerates every committed artifact for independent verification |

## Regenerate Goldens

Run with `UPDATE_GOLDEN=1` to overwrite committed golden files:

```bash
# Regenerate happy-path bundle + trace goldens
UPDATE_GOLDEN=1 go test -count=1 -run TestScaledFauxbooksEndToEnd \
    ./examples/derivation-graph/scaled/

# Regenerate happy-path HTML golden
UPDATE_GOLDEN=1 go test -count=1 -run TestScaledFauxbooksHTMLReport \
    ./examples/derivation-graph/scaled/

# Regenerate broken bundle + reconciliation goldens
UPDATE_GOLDEN=1 go test -count=1 -run TestBrokenFauxbooksEndToEnd \
    ./examples/derivation-graph/scaled/broken/

# Regenerate broken HTML golden
UPDATE_GOLDEN=1 go test -count=1 -run TestBrokenFauxbooksHTMLReport \
    ./examples/derivation-graph/scaled/broken/

# Regenerate everything in one sweep
UPDATE_GOLDEN=1 go test -count=1 ./examples/derivation-graph/scaled/...
```

Golden files must be byte-identical across Linux (amd64) and macOS (arm64). If
any platform produces different bytes, the root cause is fixed in code — no
per-platform goldens are permitted (Phase 09 DoD invariant).

If the happy-path generator (`gen/gen.go`) is ever re-run (e.g. to fix a decimal
rounding), the broken dataset in `broken/data/` and all goldens in
`broken/` must be regenerated in the same commit.
