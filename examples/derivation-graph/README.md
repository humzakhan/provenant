# Derivation Graph End-to-End Demo

This example demonstrates the full Provenant derivation graph feature:
minting leaf tokens from CSV accounting data, composing them into derived
values via `filter.sum_where`, `calc.sum`, and `calc.subtract`, and walking
the complete audit trace back to every source row.

## Dataset

Three synthetic CSV files are committed under `data/`:

| File | Rows | Accounts |
|---|---|---|
| `data/revenue.csv` | 6 | Revenue (4 rows), Refunds (2 rows) |
| `data/cogs.csv` | 4 | COGS (3 rows), Inventory adj (1 row) |
| `data/opex.csv` | 5 | Salaries (2 rows), Rent (1 row), Software (2 rows) |

Generated by `gen/gen.go` with seed 42. The CSV bytes are committed;
the test does not depend on the generator at run time.

## Derivation Graph

```
operating_income = calc.subtract(gross_margin, total_opex)
gross_margin     = calc.subtract(gross_revenue, total_cogs)
gross_revenue    = calc.subtract(net_revenue, refunds)
net_revenue      = filter.sum_where(revenue rows, account == "Revenue")
refunds          = filter.sum_where(revenue rows, account == "Refunds")
total_cogs       = calc.sum(cogs rows)
total_opex       = calc.sum(opex rows)
```

Expected values (seed 42):

| Metric | Value (USD) |
|---|---|
| net_revenue | 1,000,000.00 |
| refunds | 50,000.00 |
| gross_revenue | 950,000.00 |
| total_cogs | 400,000.00 |
| gross_margin | 550,000.00 |
| total_opex | 200,000.00 |
| **operating_income** | **350,000.00** |

## Running the Tests

```bash
go test ./examples/derivation-graph/...
```

The first run generates `golden.bundle.json` and `golden.trace.json` if they
do not exist. Subsequent runs assert byte-identical output.

## Golden Files

- `golden.bundle.json` — the JCS-canonical bundle produced by the full run
- `golden.trace.json` — the JCS-canonical trace of the `operating_income` token

Both are committed. If the derivation graph or source data changes, regenerate
them by deleting both files and re-running the tests.

## Regenerating the Dataset

To regenerate the source CSVs from scratch:

```bash
go run ./gen/gen.go --out ./data --seed 42
```

After regenerating, delete the golden files and re-run the tests to produce
new goldens. Commit all changed files together in one commit.

## Scaled demo (Phase 09)

The `scaled/` subdirectory scales the fauxbooks demo to enterprise size: 100
payroll rows, 500 expense rows, 1 200 revenue rows, and 80 refund rows — 1 980
leaf tokens in total — all flowing into a deterministic `operating_income` value.
A companion `scaled/broken/` dataset introduces two deliberate breakages (a
dropped payroll row and a tampered expense amount) to demonstrate that
`bundle.Verify` is unaffected by semantic errors while row-level CSV
reconciliation and cross-run value comparison surface the anomalies precisely.
The suite also covers the `provenant audit-html` CLI verb, which renders any
audit pack as a self-contained HTML report (no JavaScript, no network access).

See [scaled/README.md](scaled/README.md) for the full walkthrough.

## Inspecting the Trace

After running the tests, inspect the operating income trace:

```bash
# The golden trace shows the full contribution graph.
cat examples/derivation-graph/golden.trace.json | jq '.leaves[] | {source_path, leaf_value: .leaf_value, contribution}'
```

Each leaf contribution entry shows:
- `source_path` — the CSV file the value came from
- `leaf_value` — the raw amount from that row
- `contribution` — the signed amount this row contributes to operating income
  (negative for costs, zero for non-matching rows in `filter.sum_where`)

The sum of all contributions equals `operating_income.value_canonical`.
