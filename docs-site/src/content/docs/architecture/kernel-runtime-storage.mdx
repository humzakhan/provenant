Status varies by layer: the kernel provenance path is implemented now; the runtime layer, persistent storage bindings, and HITL state serialization are architecture contracts.

This page maps the boundary between Provenant's pure kernel, the optional runtime layer, and storage — precisely enough for a platform engineer, architect, or compliance reviewer to understand what the kernel is, where I/O lives, and why the audit evidence is independent of the storage choice. It summarizes the canonical architecture docs and links to them; it does not replace them. See the [Architecture Overview](/architecture/overview/) for the four-layer map and canonical invariants.

---

## The Kernel

<StatusBadge status="Implemented now" />

The kernel is the pure provenance engine. Its public Go surface (ADR-0009) has **no I/O at the public boundary** — no `net/*`, no `database/sql`, no DB driver imports anywhere transitively reachable from `kernel/`. This is not a convention: it is enforced by a CI import-guard check and a public-API snapshot test. The kernel mints provenance tokens, runs guards and validators, and emits a self-contained audit bundle as bytes.

**All I/O is injected.** The kernel defines six interfaces that the host provides at initialization:

| Interface | Responsibility |
|---|---|
| `Store` | Token and run persistence. |
| `AuditSink` | Audit entry persistence. |
| `BlobStore` | Binary blob storage for captured reads. |
| `TransactionalScope` | Transactional boundaries across `Store` and `AuditSink` writes. |
| `SourceResolver` | Resolves a logical source path to in-memory source bytes. |
| `SourceReader` | Reads and canonicalizes a source; returns a `ReadResult` carrying the extracted output and a `CapturedRead`. |
| `Clock` | Provides the current time for as-of stamping. |

The kernel does not pick, wire, or reference any concrete implementation of these interfaces. The host injects them.

**First-class in-memory binding.** The kernel ships `kernel/public/memio` (`memio.NewBinding`) as the library-mode default — it implements all required interfaces in memory. When `memio` is in use, the run is entirely in-memory and the bundle bytes are the artifact; there is no persistence layer underneath. This is the correct starting point for embedding and for use cases where the host takes responsibility for persisting the bundle bytes it receives.

**HITL state.** For pause/resume (human-in-the-loop), the kernel exposes a typed `RunState` snapshot. The **host serializes and stores these bytes**; the kernel itself persists nothing. Cross-process HITL is the host's responsibility.

See [`architecture/subsystems/kernel.md`](https://github.com/provenant/provenant/blob/main/architecture/subsystems/kernel.md) and [`architecture/adrs/0009-kernel-public-go-surface.md`](https://github.com/provenant/provenant/blob/main/architecture/adrs/0009-kernel-public-go-surface.md) for the full kernel boundary definition and surface contract.

## The Runtime Layer

<StatusBadge status="Architecture contract" />

The runtime layer is optional. A host that embeds the kernel library directly — importing `kernel/public` and wiring its own substrate — imports nothing from `runtime/`. The runtime layer exists for hosts that need a pre-built I/O implementation.

The runtime layer is **the only place I/O is implementation-specific.** It owns:

- Persistent storage bindings (see next section).
- Access-surface hosting (CLI, MCP, HTTP sidecar).

The runtime layer is **forbidden from enforcement logic.** It must call the kernel's pipeline; it may translate kernel errors into transport shapes but must not suppress, invent, or reinterpret enforcement decisions. Enforcement belongs to the kernel alone. A runtime that re-decides a `submit_answer` or bypasses the pipeline violates the architecture contract.

**Runtime storage bindings** are <StatusBadge status="Architecture contract" />:

| Binding | Path | Use case |
|---|---|---|
| SQLite | `runtime/sqlite` | Default when HITL is enabled; single-host embedded runs. |
| Postgres | `runtime/postgres` | Multi-tenant deployment. |
| S3 | `runtime/blobstore/s3` | Blob storage for captured reads. |

These bindings are specified in the architecture docs. Packaging and shipping details are outside v0 scope.

## Storage

<StatusBadge status="Architecture contract" />

Per **ADR-0011**, storage is a **deployment concern, not a kernel concern.** The kernel ships only the in-memory binding; persistent bindings live outside the kernel module under `runtime/…` and are optional.

**The audit bundle bytes are the canonical artifact.** After a run, the host decides where they live:

```
host.Persist(bundle) → disk | S3 | a DB column | nowhere
```

`provenant verify` reads only the bundle bytes. It requires no database access. The bundle is self-contained and sufficient for offline `Verify` and `Replay`.

**Why the storage choice does not change the audit evidence.** The deterministic audit-chain bytes are a function of the kernel inputs — source reads, token minting order, validation outcomes. They do not depend on which storage backend the host uses. Byte-identity is between access surfaces, not between databases.

**ADR-0008 supersession.** ADR-0008 ("Postgres as the canonical store") is superseded by ADR-0011. Postgres is now one optional runtime binding, not a kernel requirement. The ADR-0008 schema rationale remains useful reference for anyone writing a Postgres binding, but Postgres is not required to run the kernel.

**Non-Go bindings** are <StatusBadge status="Deferred" />. In v0, the embedded path is Go-only. Non-Go hosts use the runtime layer via MCP or HTTP sidecar.

See [`architecture/subsystems/storage.md`](https://github.com/provenant/provenant/blob/main/architecture/subsystems/storage.md) and [`architecture/adrs/0011-storage-is-a-deployment-concern.md`](https://github.com/provenant/provenant/blob/main/architecture/adrs/0011-storage-is-a-deployment-concern.md) for the storage boundary definition and ADR rationale.

## Caveats

<CaveatCallout title="Internally tamper-evident, not externally tamper-proof" tone="warn">
  v0 audit evidence is internally tamper-evident through hash-chain verification. Provenant can detect internal edits to bundle or audit bytes. It does NOT provide external notarization, third-party witnessing, or tamper-proof guarantees. Do not describe v0 evidence as externally attested or tamper-proof.
</CaveatCallout>

<CaveatCallout title="Byte-identity is between access surfaces, not between databases" tone="warn">
  The deterministic audit-chain bytes are a function of the kernel inputs. The storage choice — memio, SQLite, Postgres, S3, or none — does not alter them. A bundle produced by a memio run and a bundle produced by a SQLite-backed run from identical inputs are byte-identical. Do not claim that byte-identity implies any specific storage backend.
</CaveatCallout>

<CaveatCallout title="Library-mode cross-process HITL is the host's responsibility" tone="warn">
  The kernel provides the typed `RunState` snapshot for pause/resume. The kernel itself persists nothing. If your deployment requires HITL state to survive process restarts, your host must store the `RunState` bytes and restore them. This applies equally when using `memio`; there is no automatic persistence.
</CaveatCallout>
