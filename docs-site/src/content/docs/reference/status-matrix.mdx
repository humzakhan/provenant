This matrix is the overclaim guard for the launch docs. Row labels describe the current repository evidence or the architecture status, not a hosted product promise.

## Label Definitions

- <StatusBadge status="Implemented now" /> verified by current code, examples, tests, or commands.
- <StatusBadge status="Architecture contract" /> specified in architecture docs but not necessarily exposed as a current user workflow.
- <StatusBadge status="Planned" /> expected work, not current behavior.
- <StatusBadge status="Deferred" /> explicitly out of current phase or v0 scope.

## Maintenance Rules

- Use one of the four labels above near the top of every capability page.
- Add source references for every capability claim.
- Prefer `internally tamper-evident`; do not use `tamper-proof`.
- Treat Mode B host text as scratch unless `submit_answer` passed and the marker verifies against the audit chain or audit pack; require Mode A when unsigned host text is unacceptable.
- Keep regulatory language as context, not legal advice.
- Keep launch IA at or below 15 public pages.
